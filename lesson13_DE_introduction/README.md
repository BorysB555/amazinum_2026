# Data Engineering Home Task: Lecture 13
## Інструкція з запуску
Для запуску проєкту вам знадобиться лише Docker та Docker Compose. 

- Перейдіть у корінь проєкту
- Запустіть конвеєр командою:
```pwsh
docker-compose up --build
```
- Дочекайтеся появи повідомлення в терміналі: ETL ПРОЦЕС ЗАВЕРШЕНО УСПІШНО!.
- Після цього дані будуть доступні в PostgreSQL (порт 5432). Контейнер зі скриптом автоматично завершить роботу (exit code 0), а база даних залишиться доступною для перевірки.

## Звіт про очищення даних

1. Duplicate primary keys: Видалено за допомогою drop_duplicates (залишено перший унікальний запис).
2. Missing IDs: Записи без критичних ID (customer_id, order_id, product_id) видалені, оскільки вони не підлягають відновленню.
3. Invalid/Missing emails: Використано валідацію через регулярні вирази (Regex). Некоректні та порожні email видалені для забезпечення якості клієнтської бази.
4. Invalid timestamps: Рядки з некоректними датами перетворені на NaT та видалені, щоб забезпечити точність часових звітів.
5. Negative/Zero product prices: Видалено. Ціна товару обов'язково має бути додатною для коректного розрахунку виручки.
6. Unknown order statuses: Приведено до нижнього регістру. Статуси, що не входять до стандартного переліку, позначені як other.
7. Referential Integrity (Missing references):
    - Видалено замовлення, для яких не знайдено клієнта в таблиці customers.
    - Видалено позиції замовлень, які посилаються на неіснуючі товари або замовлення (Foreign Key check).
8. Invalid negative quantity: Видалено записи з від’ємною кількістю товару.
9. Mixed-case status values: Всі статуси приведені до lowercase для уніфікації.

## Аналітика (CSV-звіти)
В корені проєкту автоматично створиться папка `output/` з наступними файлами:
- `revenue_by_category.csv` — Аналіз прибутковості товарних ніш.
- `monthly_stats.csv` — Динаміка продажів по місяцях (кількість замовлень та дохід).
- `top_customers.csv` — Список найбільш лояльних клієнтів (LTV).
